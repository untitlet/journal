**Краткий анонс (250 символов):**
Модуль автоматически фиксирует все согласия пользователей на обработку ПДн с привязкой к версии текста, IP, времени и сессии. Экспорт для проверок РКН, автоудаление по срокам хранения, соответствие 152-ФЗ и GDPR. Готовая интеграция за 15 минут.

## Подробное описание

### Назначение решения

Модуль «Журнал согласий 152-ФЗ/GDPR» предназначен для формирования юридически значимой доказательной базы получения и отзыва согласий пользователей на обработку персональных данных.

Решение полностью соответствует требованиям:
- Федерального закона № 152-ФЗ «О персональных данных» (статьи 6, 9, 18)
- Общего регламента по защите данных ЕС (GDPR, статьи 7, 30)
- Рекомендаций Роскомнадзора по формированию доказательной базы

### Проблемы, которые решает модуль

1. **Отсутствие доказательств получения согласия** — при проверке РКН невозможно доказать, что пользователь действительно давал согласие
2. **Риск штрафов** — до 500 000 руб. для юрлиц по ст. 13.11 КоАП РФ
3. **Ручное ведение журналов** — администраторы вынуждены вручную собирать логи из разных источников
4. **Отсутствие версионирования** — нельзя доказать, какой именно текст согласия видел пользователь
5. **Нарушение сроков хранения** — данные хранятся бессрочно или удаляются вручную с ошибками

### Возможности модуля

#### ✅ Логирование всех согласий

Автоматическая фиксация следующих данных:
- ID пользователя (или сессия для гостей)
- IP-адрес (с возможностью последующей анонимизации)
- User-Agent браузера
- URL страницы получения согласия
- Идентификатор формы/баннера
- Дата и время с точностью до секунды
- Версия текста согласия
- Тип согласия (banner, form_checkbox, profile_update, api)
- Статус (granted/withdrawn)
- Дополнительные метаданные (JSON)

#### ✅ Версионирование текстов согласий

- Хранение всех версий текстов (политики, согласия на рассылку, cookie)
- Автоматическая деактивация старых версий при создании новых
- Привязка каждой записи лога к конкретной версии текста
- Невозможность изменить текст задним числом без аудита

#### ✅ Экспорт для проверяющих органов

- Выгрузка в CSV (UTF-8 с BOM, открывается в Excel без искажений)
- Генерация SHA-256 хэша файла для подтверждения целостности
- Фильтрация по периодам, пользователям, формам, статусам
- Пакетный экспорт больших объёмов (чанками по 10 000 записей)
- История всех выгрузок с метаданными

#### ✅ Регламентное удаление данных

- Настройка срока хранения (1/3/5/10 лет или бессрочно)
- Автоматическое удаление записей по расписанию (cron/агент)
- Анонимизация IP-адресов через заданное количество дней
- Логирование всех операций удаления в audit log
- Уведомления на email об очистке

#### ✅ Безопасность и неизменяемость

- Запрет на редактирование записей на уровне ORM
- Логирование всех попыток изменения/удаления
- Разграничение прав доступа (чтение/полный доступ)
- Защита от CSRF, XSS, SQLi через API Битрикс
- Минимизация ПДн (не сохраняются email, телефоны, имена)

#### ✅ Простая интеграция

- Автоматическое логирование из веб-форм Bitrix
- Перехват событий регистрации и авторизации
- PHP API для кастомных сценариев (3 строки кода)
- JavaScript хуки для баннеров cookie
- REST API готов к использованию

### Сценарии использования

#### Сценарий 1: Форма обратной связи
Пользователь отправляет форму → Модуль автоматически создаёт запись лога → При проверке можно доказать факт получения согласия

#### Сценарий 2: Cookie-баннер
Пользователь нажимает «Принять» → JS отправляет событие → Лог сохраняется с версией текста политики cookie

#### Сценарий 3: Регистрация пользователя
Создание аккаунта → Автоматическая запись о согласии с политикой обработки ПДн → Привязка к версии текста на дату регистрации

#### Сценарий 4: Отзыв согласия (GDPR Art. 17)
Пользователь запрашивает удаление → Logger::withdrawAll() → Создание записи об отзыве → Уведомление администратору

#### Сценарий 5: Проверка РКН
Запрос от регулятора → Экспорт записей за период → Предоставление CSV с хэш-суммой → Подтверждение целостности данных

## Инструкция по установке

### Шаг 1. Загрузка файлов

Скопируйте папку `untitlet.journal` в директорию:
```
/bitrix/modules/
```

### Шаг 2. Установка через админку

1. Авторизуйтесь как администратор
2. Перейдите: **Настройки → Настройки продукта → Модули**
3. Найдите **«Журнал согласий 152-ФЗ/GDPR (untitlet.journal)»**
4. Нажмите кнопку **«Установить»**
5. Дождитесь завершения установки

### Шаг 3. Первоначальная настройка

1. Перейдите: **Настройки → Журнал согласий → Настройки**
2. Укажите срок хранения записей (рекомендуется: 3 года)
3. Настройте анонимизацию IP (рекомендуется: 30 дней)
4. Включите логирование (галочка «Включить логирование»)
5. Укажите email для уведомлений (опционально)
6. Сохраните настройки

### Шаг 4. Создание версий текстов

1. Перейдите: **Настройки → Журнал согласий → Версии текстов**
2. Создайте версию для каждого типа согласия:
   - `privacy_policy` — политика обработки ПДн
   - `marketing` — согласие на рассылку
   - `cookies` — политика cookie
3. Скопируйте тексты ваших документов в поля HTML/Plain
4. Активируйте версии (флаг «Активная версия»)

### Шаг 5. Настройка автоочистки (Cron)

Добавьте в crontab сервера:
```bash
0 2 * * * /usr/bin/php /path/to/bitrix/modules/untitlet.journal/cron/cleanup.php
```

### Шаг 6. Проверка работы

1. Откройте любую форму на сайте
2. Отправьте форму с чекбоксом согласия
3. Перейдите: **Настройки → Журнал согласий → Записи журнала**
4. Убедитесь, что появилась новая запись

## Инструкция по использованию

### Для разработчиков

#### Быстрый старт

```php
use Untitlet\Journal\Logger;

// В коде обработки формы
if ($request->get('consent') === 'Y') {
    Logger::log([
        'user_id' => $USER->GetID(),
        'consent_code' => 'privacy_policy',
        'form_id' => 'feedback_form',
        'consent_type' => 'form_checkbox',
        'meta' => ['page' => '/contacts/']
    ]);
}
```

#### Интеграция с cookie-баннером

```javascript
// После клика «Принять»
BX.onCustomEvent('untitlet:consent:accepted', [{
    consent_code: 'cookies',
    form_id: 'cookie_banner_v2',
    consent_type: 'banner'
}]);
```

#### Отзыв согласия пользователем

```php
// По запросу пользователя (GDPR)
Logger::withdraw([
    'user_id' => $userId,
    'consent_code' => 'marketing'
]);

// Полный отзыв всех согласий
Logger::withdrawAll($userId, 'Удаление аккаунта');
```

### Для администраторов

#### Просмотр записей

1. **Настройки → Журнал согласий → Записи журнала**
2. Используйте фильтры для поиска:
   - По дате (диапазон)
   - По пользователю (ID)
   - По типу согласия
   - По статусу (granted/withdrawn)
   - По форме

#### Экспорт данных

1. Откройте страницу записей
2. Примените фильтры (если нужно)
3. Нажмите кнопку **«Экспорт в CSV»**
4. Скачайте файл
5. Проверьте хэш-сумму (отображается после экспорта)

#### Настройка прав доступа

1. **Настройки → Права доступа → Журнал согласий**
2. Назначьте права группам:
   - **Администраторы** — полный доступ (W)
   - **Менеджеры** — чтение (K)
   - **Остальные** — запрет (D)

## FAQ (Частые вопросы)

### Q: Можно ли использовать модуль на облачном Битрикс?
**A:** Да, модуль полностью совместим с Bitrix Cloud.

### Q: Нужно ли покупать дополнительные лицензии?
**A:** Нет, все функции доступны в базовой лицензии. mPDF опционален для PDF-экспорта.

### Q: Как доказать целостность данных при проверке?
**A:** Используйте CSV-экспорт с SHA-256 хэшем. Хэш сохраняется в базе и отображается в интерфейсе.

### Q: Что делать, если нужно изменить текст согласия?
**A:** Создайте новую версию текста. Старая версия останется в истории, новые записи будут ссылаться на новую версию.

### Q: Можно ли восстановить удалённые записи?
**A:** Нет, удаление необратимо. Рекомендуется регулярное резервное копирование БД.

### Q: Работает ли модуль с многосайтовостью?
**A:** Да, модуль поддерживает мультисайтовость. Записи можно фильтровать по сайту.

### Q: Как обрабатывать согласия от гостей (неавторизованных)?
**A:** Модуль автоматически сохраняет SESSION_ID для гостей. При авторизации можно связать сессию с пользователем.
